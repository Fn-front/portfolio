## 概要

生成AI（GPT-4）を活用した業務システム開発プロジェクト。PDFドキュメントのアップロード・分析、AIチャット機能を提供するクライアント向けWebアプリケーション。想定ユーザー数18,000名規模の大規模システムとして、プロジェクト立ち上げから要件定義・設計・開発までを一貫して担当。

- **参画期間**：2024年9月〜2025年9月（1年間）
- **担当範囲**：要件定義・詳細設計・フロントエンド開発
- **役割**：フロントエンドエンジニア（1名体制）
- **チーム構成**：FE 1名、BE 1名、PM 2名、デザイナー 1名

## プロジェクト背景

クライアントの業務効率化を目的とした、ドキュメント分析・AI活用システムの構築。

### 解決すべき課題

- **大量のPDFドキュメントの管理・検索が非効率**
  膨大な業務ドキュメントの中から必要な情報を探すのに多大な時間を要していた

- **ドキュメントの内容理解に多大な時間を要する**
  専門的なドキュメントの読解・理解に時間がかかり、業務効率が低下していた

- **過去の知見を活かした意思決定が困難**
  過去の事例やノウハウが活用されず、同じ問題に繰り返し対応していた

### 提案・アプローチ

これらの課題に対し、生成AIを活用したドキュメント分析・会話機能を提案。プロジェクト立ち上げから要件定義、フロントエンド全般を担当し、デザインのない画面は仕様を策定して実装を主導。

## 主な取り組み

### プロジェクト立ち上げ・環境構築

プロジェクト初期から参画し、フロントエンド開発環境を0から構築。

- Docker環境構築（ECSデプロイを想定したマルチステージビルド）
- GitHub Actions によるCI/CDパイプライン構築（ビルドチェック・ユニットテスト）
- コード品質管理ツールの導入（ESLint・Prettier・Stylelint・Markuplint）
- Next.js 14 App Router のプロジェクト設計

#### 開発効率化の工夫

開発後半からAI駆動開発（Claude Code）を導入し、コーディング・レビュー作業を支援。これにより稼働率を約20%削減し、1日あたり1〜2時間の工数削減を実現。

**AI活用の詳細**：
- 全体の約2割のコードをAI生成・支援により実装
- 特に**既存機能の改修**で高い効果を発揮（コード理解・修正提案の自動化）
- 新規実装は人間主導、AIはレビュー・リファクタリング提案に活用

### フロントエンド設計・実装

#### Next.js 14 App Router の活用

- **Server Components**：初期API取得・認証情報取得に限定し、シンプルな境界設計を実現
- **Client Components**：リアクティブなUI（フォーム、チャット等）に適用
- **API Routes**：NextAuth.jsによる認証処理を実装
- **状態管理**：SWR（APIデータキャッシュ）とJotai（認証状態管理）を役割分担
- **Middleware活用**：ユーザーロールによるページアクセス制御を実装（学習コストは高いが柔軟な権限管理を実現）

**パフォーマンス最適化**：
- Next.js Image コンポーネントによる画像最適化（自動WebP変換・遅延ロード）
- React.memo による不要な再レンダリング抑制
- コンポーネント粒度の適切な設計でパフォーマンスとメンテナンス性を両立

#### デザインシステムの構築

- Radix UI + Shadcn UI による再利用可能なコンポーネント設計
- アクセシビリティ WCAG 2.1 AA 準拠（キーボード操作・スクリーンリーダー対応）
- Radix UIのヘッドレス設計により、ロジックとスタイルを分離

#### 認証・セキュリティ設計

- **NextAuth.js による認証制御**：フロントエンドでの認証情報保持・ログイン制御を実装
- **バックエンド認証連携**：実際の認証処理はバックエンドAPIで実施し、フロントは状態管理のみ
- **署名付きURL**：S3への直接アップロードに署名付きURLを使用し、セキュアなファイル転送を実現

### コア機能の実装

#### AIチャット機能（技術的挑戦度：高）

GPT-4を活用したストリーミングレスポンス型チャット機能を実装。

- **ストリーミング処理**：`@microsoft/fetch-event-source` による Server-Sent Events（SSE）実装
- **リアルタイム表示**：1文字ずつタイプライターアニメーションで表示
- **スクロール制御**：ユーザーのスクロール位置を検知し、自動スクロールを制御
- **会話履歴管理**：各リクエストごとに会話履歴を送信（サーバー側で履歴保持なし）
- **エラーハンドリング**：ネットワークエラー時の再接続制御
- **Markdownレンダリング**：React Markdownを使用し、AIの回答をリッチテキストで表示

AIチャットに加え、**PDFドキュメントのAI分析機能**も実装。ユーザーがアップロードしたドキュメントをGPT-4で分析し、要約・重要ポイント抽出をMarkdown形式で表示。

#### マルチパートアップロード機能（技術的挑戦度：高）

最大10GBのPDFファイルをチャンク分割してアップロード。

- **チャンクサイズ**：100MB単位で分割
- **並列アップロード**：同時実行数2で制御、サーバー負荷と速度のバランスを最適化
- **高速アップロード**：1GBあたり5〜8秒で処理、10GB全体でも1分程度で完了
- **プログレス表示**：アップロード進捗をリアルタイムで表示
- **リトライ制御**：失敗時は3回まで自動リトライ、規定回数を超えたら中断
- **署名付きURL**：S3への直接アップロードによるセキュアな実装
- **ステータス管理**：アップロード中・完了・エラーを視覚的にフィードバック

#### データ可視化機能

Rechartsを使用し、ユーザーが投稿したフォームデータの統計分析・可視化機能を実装。

- 期間別・カテゴリ別の集計データをグラフ表示
- 複数の可視化パターン（棒グラフ・折れ線グラフ等）に対応
- レスポンシブデザインでモバイル表示にも対応

### フォーム・UI/UX設計

#### react-hook-form + Zod によるフォーム設計

堅牢で使いやすいフォームバリデーションを実装。

- **フォーカスアウトバリデーション**：入力中にエラーを表示せず、離脱時に検証してUXを向上

#### UI/UX設計とデザイン提案

## 技術的な課題と解決

### 課題1：AIチャット機能のストリーミング制御

GPT-4のストリーミングレスポンスを滑らかに表示しつつ、ユーザー操作を妨げない実装が課題。

- **アニメーション制御**：タイムアウト制御により1文字ずつ滑らかに表示
- **スクロール制御**：ユーザーが手動スクロール中は自動スクロールを停止
- **エラーハンドリング**：ネットワーク切断時の適切なエラー表示

ユーザーが違和感なく会話できるUXを実現し、クライアントから高評価を獲得。

### 課題2：大容量ファイルアップロードの安定性

10GBのPDFファイルを確実にアップロードするため、ネットワーク不安定時の対応が必須。

- **リトライ機構**：失敗時は自動リトライ（最大3回）、規定回数超過で中断
- **並列アップロード制御**：同時実行数を制限し、サーバー負荷を軽減
- **プログレス表示**：ユーザーに進捗状況を明確に伝える

安定したアップロード処理を実現し、ユーザーの不安を解消。

### 課題3：Next.js バージョンアップによる破壊的変更

開発途中でNext.jsのマイナーバージョンアップを実施した際、Middlewareでのcookie処理仕様が変更され対応が必要に。

- **問題の詳細**：Middlewareでのcookie読み書きAPIが変更され、既存の認証制御が動作不良
- **解決アプローチ**：公式ドキュメント・GitHubのIssueを調査し、新しいAPI仕様に移行
- **影響範囲の特定**：認証関連のMiddlewareを集中的にテストし、早期に問題を解決

バージョンアップの影響を最小限に抑え、迅速に対応完了。
